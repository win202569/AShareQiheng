## 1. 目标与范围

将已完成的“证据齐全、但尚未应用政策的七维算术”连接到周期保护、绝对红线、独立状态和最终评分。采用三个独立验收阶段：

| 阶段 | 产物 | 明确不能宣称的能力 |
| --- | --- | --- |
| A：合同层 | 同一签名注册图下、类型明确且不可变的政策定义；字段、版本、规则覆盖和引用的静态校验 | 不证明证券已具备运行证据，不执行政策，不生成最终分数 |
| B：证据与政策结果 | 当前冻结输入下的政策证据及政策结果；明确待补、否决、封顶及利润正常化依据 | 不把未调整估值的既有分位数当作最终分位数 |
| C：最终评分集成 | 重建受影响的完整估值同行样本，重算分位数、置信度和最终评分卡 | 不自动发布，不跳过后续股票池选择、V7 持久化和发布校验 |

本规格为阶段 A 给出合同结构、验证责任和验收标准；第 7、8 节固定阶段 B/C 不可突破的集成边界。阶段 B/C 的取数执行器、具体新行情值格式和利润调整计算适配器须有各自的完整实现规格后才能开发，不能由阶段 A 的完成状态推导它们已实现。

阶段 A 新增 `ashare_pipeline/formal_policy_registry.py` 与对应测试。可抽出一个只负责规则结构/类型校验的 `formal_policy_contract.py`，但不得新增通用表达式引擎。现有生产模块仅在实施计划证明必需时加入最窄适配；不得重写 V2–V6 DDL、已有财务公式、指标排名或评分算术。

## 2. 保持不变的边界

- 冻结时点为北京时间 2026-08-31 15:00（UTC 07:00）；SH/SZ/BJ 普通 A 股统一处理。
- 保留五模板、七维权重、各维内部权重及现有精确 Decimal 算术合同。等级不能替代未经显示舍入的分数比较。
- 同行资格始终是指标级资格，不能按“七维完整”“可入池”或“未被否决”过滤同行。
- 缺失、冲突和无效分母不填零、不填行业中位数、不改权重。
- 周期行业由冻结的行业清单确定。连续五 FY、两个指标同时达到自身历史 80 分位、G/M 最高 80、当期利润与五年利润中位数取低者的规则不变。
- ST/*ST、退市整理、强制退市风险、治理红灯、权益/净资产非正、不合格审计意见、连续 20 个交易日无有效成交等既定硬否决不减弱。
- 最多强池 20 只、等待池 50 只；行业上限分别 4/10；两个池的阈值、排序及不得互相转移的规则不变。
- 原 `PrePolicyScoreCalculation` 继续明确标识 `pre_policy`，不能借改字段名升级为最终评分卡。
- 新输入、新规则或更正形成新身份。保留所有历史数据、SQLite、进度与旧发布，不原地覆盖、不自动合并 main、不推送。

## 3. 注册图与兼容方式

### 3.1 不新增注册图角色

继续使用同一根清单绑定的 source、mapping、feature、scoring、industry、cyclic、redline、status、event 九个角色。政策加载器只读取该根图中四个政策子项，不接受单独传入的 unsigned dict、局部规则文件或调用者覆盖项。

保留政策子项现有六键：`registry_role/schema_version/purpose/registry_version/source_evidence_categories/rules`，其中外层 `schema_version` 仍为 `formal-scoring-policy-v1`。scoring wrapper 保持既有 v1/v2 格式。

在每个政策子项的 `rules` 内新增独立入口 `execution_contract`：

| 字段 | 约束 |
| --- | --- |
| schema_version | `formal-policy-execution-contract-v1` |
| role | 与所在政策子项角色完全相同 |
| rule_ids | 非空、按字符串升序排列、无重复的显式活动规则 ID 数组；不能包含入口自身 |

四个入口均必须存在。入口引用的规则必须存在于本角色内、使用支持的规则版本，且全部通过类型检查。其他既有规则仍保留原语义；未列入活动入口的规则不得自动执行。活动规则必须覆盖本规格规定的必需语义，不能通过不登记某条硬否决将其关闭。活动规则不得具有额外未知字段。

现有 scoring 的 redlines、status_rules、market_liquidity_rule 引用，以及各指标声明的政策引用，除下述周期 classification 外，都必须在对应活动入口中出现；不能只保留旧引用而跳过执行。规则族的角色固定为 cyclic_protection→cyclic、numeric_redline→redline、market_liquidity→status、boolean_state/enum_state→status 或 event。政策入口可以补充同模板其他必需规则，但不能改变旧引用的含义。

原 `classification` 规则仍仅含 `secondary_industries`，不向其中追加周期运算字段，不据行业名称猜测周期归属。新增周期执行规则单独保存。

### 3.2 兼容格式不等于复用签名

任何子项内容变化都会改变子项哈希。对应 scoring `policy_contracts` 的哈希、版本和证据类别必须同步一致；scoring 子项和根清单也须重新产生内容身份并按既有制度签署。

旧 wrapper 的格式和旧历史字节继续可读，但新内容不能冒用旧签名、旧根哈希或旧评分输入。阶段 A 不为任何生产配置签名，也不把软件测试密钥作为生产批准。

### 3.3 加载器接口和权限

拟定入口：

`load_formal_policy_registry(bundle, *, scoring_registry, feature_registry) -> FormalPolicyRegistry`

三个参数均为既有精确、封闭验证类型，必须来自同一根图；不能接受浅拷贝、公开结构值或只凭哈希字符串声明的同根关系。加载时调用既有正式资格检查，并重新核对九角色哈希、政策子项版本/类别以及 feature 的 source/mapping 绑定。

`FormalPolicyRegistry` 暴露不可变的规则、依赖声明、角色/根哈希、合同版本、规范序列化和 `require_verified()`。它只证明规则定义和静态绑定已验证；不暴露 `policy_ready`、`pool_eligible` 或“证据齐全”布尔值，不提供制成最终分数的入口。直接构造、复制、普通属性/方法/继承替换不得绕过读取时的验证；不声称防御解释器或元类底层被任意改写。

## 4. 类型化取数声明

不支持 SQL、JSONPath、Python 回调、任意原始响应路径或运行时传入的证券 ID。证券身份由后续工厂从冻结全量宇宙确定；字段选择器只能引用本根图内声明的字段。

### 4.1 财务标量

一个财务选择器必须声明：`kind=feature`、`template_id`、`feature_key`、`expected_unit`、`formula_version`、`period_keys`。

- `feature_key` 必须在同模板的 `SignedFormalFeatureRegistry.slots_for_template()` 中存在。
- 单位、公式版本必须与该签名槽位完全一致。不得暗中将百分数、比例、元、万元等作换算。
- `period_keys` 是按规范排序的去重数组，必须等于该槽位签名公式 AST 的全部 fact 叶子期间集合；不能凭槽位名称推断期间。
- 政策可以声明一个既有可选特征为本规则运行时必需，但不能修改原槽位的 required 属性或改变旧 V6 完整度规则。
- 阶段 A 不接收任何特征的实际数值。

### 4.2 年度观察序列

序列选择器声明 `kind=annual_series`，并提供按年度升序排列的 `observations`。每项包含目标 `fy_end` 以及一个完整财务标量选择器。

周期所需序列必须恰好包含 FY2021–FY2025 五个不同观察点，不允许复制一个标量充当多年度数据，不允许用任意旧年度凑数。声明的目标 FY 标签只表明观察点，不能代替运行期的真实期间证明。

一个年度 ROE 可以合法依赖期初、期末两年资产负债数据；不能强求它的所有原始事实都属于目标年度。阶段 B 必须用原始 fact 身份和已签名公式核对每个实际依赖期间、单位与计算口径。现有 `FormalEvidenceRef` 本身没有期间字段，不能只查看引用数组长度或通用 history_endpoints 就认定系列完整。

### 4.3 Context 选择器

Context 选择器声明 `kind=context`、`descriptor_id`、`context_kind`、`scope_key`、`field`、`entry_id`、`expected_type`、`expected_unit`。无需 entry ID 或单位的类型必须显式为 null，不补默认值。

`descriptor_id` 为规范化描述符 ENTRY 的 SHA-256，不是整份 scoring wrapper 的哈希。加载器匹配同根签名描述符及证券作用域、请求证券、来源、解析/映射版本；实际读取仍通过现有解析器和 Context repository，不新增按任意 ID 直接取行的通道。

字段为以下有限类型，不是路径表达式：

| Context | 可声明值 | 限制 |
| --- | --- | --- |
| security_state | is_st、is_star_st、listing_status、forced_delist_risk、suspended | 精确布尔或已有枚举；不能把 suspended 单独升级为新的硬否决 |
| regulatory_state | 指定 flag_id 的 active | ID 必须在描述符白名单；缺少该 flag 不等于已证明 false |
| event_calendar | 指定 event_id 的有日期、单位及 quantified_value 的记录 | ID/单位必须匹配；无量化值不能伪造零 |
| market_close | 完整已验证行情记录 | 不单凭 stale_trading_days 宣称整个历史窗口已验证 |
| trading_calendar | 完整已验证交易日历 | 使用签名交易所/日历选择器；不能用工作日代替交易日 |

类型与字段不匹配、越权 flag/event ID、全市场描述符冒充单证券描述符或不同证券字段混用，均为合同错误。现有 market_close 的正收盘价值格式保持不变；它不能承载“确认无有效收盘价”。该新增证据格式的实现属于阶段 B，阶段 A 不放宽旧值验证。

## 5. 规则结构与已批准语义

每条活动规则声明 `schema_version=formal-policy-rule-v1`、`kind`、唯一 `semantic_id`、`template_id`、`inputs`、`parameters`、`outcomes`。每条规则只针对一个现有模板；同一模板内不得重复定义同一必需语义。必须显式覆盖全部五模板的必需合同；这不意味着非周期公司也需要五年周期取数。

`outcomes` 必须包含 `on_match`、`on_clear`、`on_missing`、`on_conflict`。后两者固定为 `pending_evidence`；on_clear 固定为空结果数组；on_match 为该规则族允许的类型化结果。规则编译和版本/哈希错误不通过该字段降级成普通证券待补。

结果类型仅有：`dimension_cap`（维度及有限 0–100 上限）、`pool_prohibition`（strong/wait/both）、`valuation_profit_basis`（被验证的正常化利润依据）、`independent_status`（已登记状态）、`pending_evidence`（带已登记原因码的待补要求）。结果中没有“设为某个总分”或“手动指定排名/入池”的类型。

### 5.1 周期规则

`kind=cyclic_protection` 的 inputs 为 current_roe、current_margin、current_profit 三个标量，以及 annual_roe、annual_margin、annual_profit 三个完整年度序列。

parameters 明确写入五个 FY、quantile_method、quantile_level、median_method 和 profit_basis_method；不能缺省。量化门槛固定为 `0.80`，利润方法固定为当期利润与五年利润中位数取低。on_match 明确含 G/M 两项 80 分封顶及正常化利润依据。

首版软件合同允许以下显式算法标识；允许某算法不等于已选择生产算法：

- `linear_type7_v1`：升序 x，n=5，h=(n-1)p；取零基 floor(h) 对应值与其后一值做线性插值，端点取端点值。
- `nearest_rank_v1`：升序 x，取一基 ceil(n*p) 对应值，p 固定 0.80。
- 五年中位数算法标识为 `ordered_middle_v1`：对五个已验证利润值排序，取第三个；不对两值平均。

例如序列 1、2、3、4、5 的 80 分位，前两种算法分别为 4.2 和 4。这个例子说明算法为何必须显式固定，不是生产政策选择。生产配置必须签名声明所用算法；未知版本和缺失值拒绝加载。所有未来运算沿用固定 precision=50、ROUND_HALF_EVEN 的 Decimal 合同。

只有签名清单内公司的完整周期证据触发周期判断。未触发顶部仍保留完整证据与判定轨迹；清单外不运行周期取数，更不能因名字含“资源”等词施加周期政策。

### 5.2 数值红线

`kind=numeric_redline` 使用一个财务标量，parameters 明确 comparator（lt/lte/gt/gte/eq 之一）及有限 Decimal 字符串 threshold；阈值的单位等于输入的已签名单位。on_match 仅可产生已登记模块封顶、双池/单池禁止、独立状态或待补证据要求，不修改原始事实和指标分位数。

本阶段不为金融等价指标猜阈值。已批准的权益或净资产非正语义使用 lte/0，并必须禁止双池；具体是哪个有同等含义的源字段，由生产签名映射声明，不能从测试特征名称推导。

### 5.3 布尔和枚举状态

`kind=boolean_state` 使用精确布尔选择器和显式 expected；`kind=enum_state` 使用既有枚举选择器和显式非空 values 集合。

必需硬否决语义覆盖：st、star_st、delisting_arrangement、forced_delist_risk、governance_red、nonpositive_equity、audit_qualified、audit_adverse、audit_disclaimer、no_effective_trade_20d。证券标签和退市状态绑定已签名 security_state；治理及审计意见绑定已授权监管旗标；非正权益使用第 5.2 节的财务数值规则；无有效成交使用第 5.4 节的市场规则。语义标签不能代替来源证据。上述每项匹配时禁止双池；不得把治理红灯遗漏为普通提示。

审计意见和治理等级可以使用已有 regulatory_state 的显式旗标，但必须将所用 flag_id 与语义关系登记在生产合同内。没有旗标、缺少响应、未覆盖的意见代码不等于审计通过或治理安全。

治理橙灯、拥挤、重大解禁/减持窗口、重大事件和周期顶部必须保留为独立、带证据的状态，不是新的统一双池硬否决。前五类分别由显式状态规则覆盖，周期顶部由周期规则同时产生状态结果；各模板均须声明相应覆盖，不能用空事件入口绕过。生产合同必须明确其禁止 strong/wait/both 的选择；软件不自行决定具体生产事件的严重度。非量化事件不能使用 event_calendar.quantified_value 冒充评分输入。阶段 B 可复用已授权监管旗标；需要额外结构时，先采用新的版本化格式，保留旧格式。

### 5.4 市场流动性规则

`kind=market_liquidity` 绑定完整市场记录和交易日历，parameters 固定有效成交判定为 exchange_allows_trading 且 volume>0 且 turnover>0，硬否决阈值为 20 个连续交易日，无有效收盘价搜索窗口为 250 个交易日。

规则同时声明依赖 `verified_market_window_v1` 证据能力。这是阶段 B 必须提供的能力要求，不是第一阶段已经存在的事实类型、描述符或可执行适配器。阶段 A 只校验该固定依赖声明，不能用已有市场记录替代它的证明。

运行时要求：

- 有效成交当日：实际正收盘价、实际日期与冻结日一致。
- 停滞 1–19 个交易日：可以使用实际已验证的最近有效收盘价及日期，并保留停滞状态；不能使用 preclose 替代。
- 连续至少 20 个交易日无有效成交：产生既定双池硬否决。
- 250 个交易日内确认没有有效收盘价：给出 market_evidence_missing，不能计算依赖价格的最终分数。
- 搜索窗口不完整、抓取失败、缺少响应：是证据不足，不能声明“已确认没有收盘价”。
- 已知超过 250 日之前的旧收盘价，也不能当作该窗口内的有效价格。可同时保留已证明的停滞否决，但证据不足优先阻止最终分数。

停滞状态不能在此层换算成额外 T 分。T 的映射必须经单独已签名指标定义和证据路径计算，避免政策层任意加减分。

### 5.5 利润正常化的估值依赖声明

周期合同必须列出受正常化影响的维度限定估值 metric_id、所依赖的正常化利润语义，以及版本化计算适配器的身份。映射不得指向 G/M 等非 V 指标，不得声明替换最终 percentile。

每项声明字段固定为 metric_id、policy_dependency（affected/unaffected）、profit_semantic_id、adapter_id、adapter_version、definition_basis；依赖身份字段 profit_semantic_id/adapter_id/adapter_version 对 affected 必须非空，对 unaffected 必须显式为 null。definition_basis 为非空的签名定义依据，不是运行期证明。

阶段 A 校验目标确实属于相同模板的 V 定义、引用唯一、版本和依赖显式存在，输出未执行的依赖声明。它不把旧 `op=feature` 公式解释为已支持利润替换，也不证明一个仅有名称的适配器已经实现。阶段 C 必须拒绝没有已实现且受信任的对应适配器的运行；适配器的具体公式和完整操作数绑定应由阶段 C 的规格定义并版本化。

允许保留确实不受该利润正常化影响的 V 指标，但需在完整 V 依赖清单中显式标为 unaffected，并给出签名的定义依据；不能默认所有 V 指标都要调整，也不能默认都不受影响。软件支持声明不等于替生产配置批准经济等价关系。

## 6. 静态校验与失败分类

阶段 A 一次加载四个政策角色并输出一个闭合不可变定义图，按以下顺序校验：

1. 根、子项、审批用途、签名验证身份及现有评分/特征注册表的同根关系。
2. 四个 execution_contract 入口、活动 ID、规则版本、精确字段及类型。
3. 模板、semantic_id 唯一性、硬否决和周期/市场的完整合同覆盖。
4. 选择器的同根签名特征与描述符身份，单位、公式、期间、flag/event 白名单。
5. 固定常量、允许运算、结果目标、全量 V 依赖声明及引用闭合。
6. 构建规范序列化和合同哈希；哈希绑定完整根身份、四子项内容身份及解析合同版本，不形成自引用。

合同校验失败（如缺角色、未知字段/版本、哈希不匹配、越权引用、漏掉硬否决）抛出明确的合同错误，不能返回看似合格的空规则集。解析器可区分 malformed_contract 与 unsupported_contract，但两者都不能供正式政策执行。

实际数值/行情/监管响应缺失属于阶段 B 的运行问题。阶段 A 没有数据库查证和证券状态写入职责，不制造 pending 证券，也不将“合同有效”写为 formal_scored。

## 7. 阶段 B 必须遵守的证据边界

- 由工厂自行枚举冻结宇宙、取得真实同根当前特征及 Context；不接收调用者的 cyclic/ST/年数/收盘价/无覆盖布尔值或预制政策结果。
- 沿用当前 provider/数据库代际一致性检查和来源重验。文件篡改、领先版本冲突、来源替换及批次内更正中止相应尝试，不能通过捕获错误字符串当作缺失。
- 年度序列逐点证明；通用“四/五年历史已出现”的数组不能替代 ROE、利润率、利润各自的完整系列。
- `verified_market_window_v1` 必须绑定实际交易所日历、请求范围、所需搜索区间内每个交易日的覆盖及最近有效成交证据。找到有效成交时，证明其后到冻结日的全部交易日即可停止回溯；声明 250 日内确认无价格则必须证明完整 250 日区间，不能提前停止或跳日。新的值格式必须有显式的正价格/确认无价格判别，不能把旧 market_close 的字段由正数悄悄改为 nullable。
- 运行结果区分 matched、clear、not_applicable、pending_evidence；无响应不能推断 clear。事实冲突阻止正式评分，不伪装为已证明的否决。
- 多个模块封顶取最严上限，多个禁止池结果取并集；保留所有触发依据。已存在否决不能抵消缺失的必需证据；pending 仍阻止完整最终分数。
- 证据和政策结果都须封闭验证、不可变并携带可撤销的来源关系。生成过程中失效的上游不能留下有效的下游政策证明；成功结果可以作为历史审计对象保留。

## 8. 阶段 C 必须遵守的计算边界

1. 先根据实际政策证据生成利润正常化依据；对每个受影响 V 指标使用已版本化并验证过完整操作数的计算适配器。
2. 在全量冻结宇宙内重算受影响指标原始值和指标级资格，重建二级/一级同行样本，重新执行 N>=20 门槛及原分位数公式。
3. 任何受影响公司的原始 V 值变化，都可能改变非周期同行的排名；因此不能只重算周期公司，不能复用旧样本排名再事后扣分。
4. 在指标聚合后应用 G/M 及其他已登记模块上限，保留原始与封顶后两个结果。
5. 正常化新引入的五年利润等证据必须加入最终槽位的依赖和最低时点精度，重算全局 P、其他置信度分量及 C；无一致预期的既有 0.90 上限仍适用。
6. 从最终维度和置信度重算 Sc、B、R安全、风险暴露及正向分数等级。未量化重大事件不进入 T 的伪精确分数。
7. 最终评分卡必须验证同根、同冻结输入、同一批次政策/调整后指标的来源关系；PrePolicyScoreCalculation 单独永远不满足该入口。
8. 只有上述完成后才交给后续 Task 5 的确定性选池。阶段 C 不绕过 V7/发布验证，也不修改旧输出。

## 9. 阶段 A 验收

全部离线，使用真实字节敏感签名的合成注册图。测试模拟政策不等于生产规则获批。

- 完整四角色入口和五模板声明能生成不可变合同，规范序列化/哈希确定；合同对象不能当政策执行结果或评分输入。
- 原政策外层格式、scoring v1/v2 和 classification 旧语义保持兼容；无 execution_contract 的旧根仍可用于原有 pre-policy 接口，但新合同加载明确失败。
- 每个未知键、未知规则/算法版本、重复/悬空活动 ID、空入口、漏掉 scoring 已引用规则或必需语义、跨角色/模板引用、不同根、哈希/版本/类别不一致均失败。
- 财务特征不存在、单位/公式版本/AST 期间不符、重复 FY 或用一个特征凑五年、未授权 flag/event ID 均失败。
- 明确证明两种 80 分位算法标识没有默认；阶段 A 只验证登记，不选择生产方法，不执行经济运算。
- 20/250 天及周期常量不允许通过配置降低；新增数值红线必须有明确签名值，测试不得把任意样例阈值当生产批准。
- 替换调用依赖、复制/伪造合同对象、普通方法/属性/继承影子不得绕过合同读取验证；保持既有可信运行时边界，不做无关的解释器防篡改扩展。
- 正常化适配器和市场窗口能力的声明不能被当作其已实现或运行证据齐全的证明。
- 原注册表与受影响 Context/feature 合同测试按改动范围回归；不为纯合同检查反复构造完整 22 证券、多年事实的昂贵取数样本。
- 本阶段不改生产数据、不抓取、不写 SQLite、不生成股票池或正式报告。

## 10. 文档审批与实施顺序

本规格的复核批准只授权软件合同结构及以上阶段边界。它不选择某个生产分位数算法，不批准真实证券字段映射、额外经济阈值或生产签名。

复核通过后先为阶段 A 编写独立实施计划，按合同解析、同根绑定及兼容/失败场景形成可单独测试的任务，并由子代理实施和独立审查。阶段 A 验收后再设计阶段 B 的新增证据值格式与取数工厂，阶段 C 设计调整计算适配器和最终评分入口。阶段之间不重复询问已确认的七维权重、冻结时点、股票池容量或硬排除条件。

## 11. 设计取舍与复核记录

- 选择分阶段验证而非一次联调整段：代价是新增定义层接口，收益是能分别定位合同错误、证据缺口与计算问题；不以中间结果冒充最终分数。
- 保留政策外层和 scoring wrapper 版本，新增规则级合同：代价是任何真实内容更新仍要更新全部依赖哈希并重签；不能假装旧字节可继续代表新规则。
- 同时登记两种明确分位数算法能力，不设默认：代价是生产配置必须做一次显式选择；本次软件设计不替代该审批。
- 单独维护实际年度系列与市场窗口证明：代价是阶段 B 需要真实取数和覆盖审计；不复用仅有外观完整的年度标签或空响应。
- 最终信心分随新证据一起重算：代价是正常化可能影响同行、最终置信度和选池整体；不能仅修补某只股票的 V 分。

自检要求：规则与证据权限分离、旧值格式不变、所有必需语义不遗漏、生产值与软件能力分离、阶段 A 不越界执行阶段 B/C。书面规格复核完成前，不开始实现代码。
