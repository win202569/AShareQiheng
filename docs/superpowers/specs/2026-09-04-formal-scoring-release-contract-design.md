## 1. 目的、适用范围与优先级

本规格把已确认的研究政策转换为可实施、可审计、失败关闭的正式评分合同。它覆盖全部在冻结日属于中国内地 A 股普通股的证券，包括沪深北市场、科创板和创业板；B 股、基金、ETF、债券、可转债和 REIT 不在本合同范围内。ST、退市整理证券和暂停交易证券仍须出现在全量清单中，但可能被标记为池否决。

本规格是对 [SCORING_SPEC_V2.md](../../../SCORING_SPEC_V2.md) 的显式 V3 政策修订，而不只是补全未定细节。表 1.1 中列出的已确认变更在正式 release 中替代相应的 V2 条款；未列出的 V2 防过拟合、证据优先、治理/事件单列和失败关闭原则继续有效。此前的预筛、feature-contract-v1、历史试验 score run 和任何已发布产物不被追溯修改。

本规格不是投资建议，也不允许用未完成的采集或估算结果伪装成全市场结论。

## 3. 时点与全量宇宙合同

### 3.1 冻结时间

正式评分的时点为 2026-08-31 15:00:00 Asia/Shanghai。所有输入均须证明其公开时间不晚于该时点：

- 交易价格、成交量、停复牌和证券状态使用 8 月 31 日收盘数据；
- 有精确公开时间的财报、公告、监管文书，要求公开时间小于或等于冻结时间；
- 来源只有公告日期而没有时分秒时，为避免前视偏差，按该日期 23:59:59 记录，最早在下一交易日收盘后生效；
- 截止日后发布或修订的值不得回填到本发布版本，即使其报告期早于冻结日；在冻结日后才抓取到的原文可以用于历史重建，但仅当原文可验证地证明 published_at 与 effective_at 均不晚于冻结日；
- 同一事实有多个截止日前版本时，按公开时间、源更新时间、抓取时间、内容哈希的固定顺序选取。排序不得依赖网络返回顺序。

正式模块必须使用单独的 market_close_as_of 时间参数；不得复用旧预筛或特征管线中以当日 23:59:59 作为通用截止的逻辑。多版本选择按公开时间降序、源更新时间降序、抓取时间降序、内容哈希升序；空的源更新时间排在有值之后。

有效成交定义为交易所状态允许交易且当日成交量和成交额均大于零。冻结日没有有效成交时，市场事实记录最近一个有效成交日的收盘价及 stale_trading_days，不能把旧 preclose 伪装成 8 月 31 日收盘价。连续 1 至 19 个交易日无有效成交时，估值 V 可使用最近有效收盘价但必须携带停牌/陈旧价格状态，T 的流动性项必须消费该状态；连续 20 个或以上交易日无有效成交时，按第 8.1 节硬否决。过去 250 个交易日内没有任何有效收盘价时，市场证据为 pending_evidence。

### 3.2 宇宙快照与状态清单

每个 release 都固定一个按 security_id 排序的 universe snapshot，并计算 universe_hash。每只证券必须且只能进入以下状态之一：

1. formal_scored：满足所有正式合同，拥有七维分数；
2. pending_evidence：有明确缺失、重试或待验证原因；
3. pool_vetoed：可展示已完成评分或风险轨迹，但因硬否决不得入池；
4. out_of_scope：不属于 A 股普通股范围，并记录范围原因。

任何未分类证券、重复证券、无哈希的宇宙行、失效快照或未来数据都会阻断官方发布。已完成子集可以输出为 preview，但必须带醒目标记，不能称为正式评分或正式股票池。

universe_status 是独立于旧 score_item.status 的全量状态表，不能复用后者的 pending、partial、ready、blocked 或 final 枚举。状态优先级固定为：out_of_scope；其后是 pending_evidence；其后是 pool_vetoed；最后是 formal_scored。也就是说，ST 且财报缺失的证券状态为 pending_evidence，并在独立 veto_flags 中保留 ST 标记；只有证据完整后才可成为 pool_vetoed。北交所规范证券 ID 为 BJ 加六位代码；实现必须先完成该身份校验、冻结日状态快照和来源适配，不能沿用只接受 SH/SZ 的旧校验。

## 4. 证据合同与来源边界

### 4.1 原始快照

每份原始快照均不可修改，至少保存：

- source、dataset、请求指纹和原始 URL；
- payload 的规范 SHA-256；
- 证券身份、报告期或市场日期；
- published_at、source_updated_at、captured_at 和适用的 effective_at；
- 解析版本、字段映射版本和验签结果。

规范事实、特征、分数、池成员和发布清单只能引用已验签的原始快照。任一数据源或版本变化都必须形成新的 input_hash，旧产物继续保留。

本合同中的“验签”是可复验的证据验证，不假定来源提供密码学数字签名：保存的原始字节须与规范内容哈希一致；URL 主机须在正式来源白名单；文档或响应须能校验证券、期间和来源身份；公开时间、抓取时间与解析字段须相互一致。旧 source_snapshot 若只保存请求指纹、哈希、路径和抓取时间，不能直接升级为正式证据，必须补采或以可验证原文补齐本节字段。

### 4.2 权威来源

| 数据类别 | 正式证据 | 规则 |
|---|---|---|
| 法定财报、审计或审阅意见、公司公告 | 巨潮资讯原始披露 | 保存原文或可验签原始响应与披露时点。 |
| 价格、成交、停复牌、证券状态 | 上交所、深交所、北交所原始市场数据 | 收盘日的可验证记录必需。 |
| 监管、处分、退市、重大违法事项 | 交易所或证监会原始公告 | 不能只引用新闻转载或第三方摘要。 |
| 行业分类 | 冻结的申万 2021 二级行业快照 | 保存版本、抓取来源、有效日期和完整映射哈希。 |
| 股本、分红、回购、融资、并购 | 法定报告或正式公告 | 宣布但尚未完成的回购不计为现金回报。 |
| 一致预期 | 带可验证发布时间或 as-of 的公开快照 | 无法证明冻结日已公开时不得使用。 |

AkShare、BaoStock 和其他第三方库仅可承担抓取、发现和交叉校验职责，不能单独构成正式证据。其响应可保留为辅助快照，但正式事实必须能回溯至上表的权威来源。

正式来源适配器、URL 白名单和验签解析器是首个 official release 的前置交付物。只有 AkShare/BaoStock 证据的证券必须保持 pending_evidence；实现不得以当前第三方适配器的成功响应解除该状态。

### 4.3 一致预期的无覆盖规则

预期来源成功返回、但明确显示该证券没有有效一致预期覆盖时，这是一种可验证的无覆盖状态，不是把缺失填成利好：

- 买点 T 的预期变化子项固定为 50 分；
- 总置信度 C 在其他公式计算后取 min(C, 0.90)；
- 其余 T 证据完整时，证券仍可参加正式评分；
- 无可验证日期、来源故障、响应不完整或无法确认历史截点时，属于 pending_evidence，而不是无覆盖。

## 5. 增量采集、状态机与数据保留

任务的自然键为：security_id、数据类别、报告期或市场日期、来源、冻结日和请求版本。任务状态至少为 pending、leased、verified、retryable_failed、terminal_failed、superseded。每次成功先持久化并验签单个快照，再离线重建受影响证券的事实、特征和评分输入；不得把跨证券的网络调用放入数据库事务。

重启时只租用未完成、租约过期或已到重试窗口的任务。已验证、同请求指纹且内容一致的快照不得重复抓取。单证券或单来源失败不得中断其他任务；403、429、验证码和挑战页应触发同源熔断，超时或临时空响应可按有限退避重试。

原始快照、标准化事实、特征、正式发布包和审计清单都是需保留的数据。SQLite 的 WAL/SHM、进程锁、运行时状态文件和临时渲染文件可重建，不是证据本体。正式发布产物保存到 data/releases/<release_id>/，不依赖被忽略的临时 outputs 目录。

## 6. 正式特征与置信度 C

### 6.1 最低历史门槛

正式评分要求至少连续 3 个完整财年和最近 8 个可比季度。这里的“三个完整财年”定义为三个完整年度间隔：在 FY2025 为最新年报时，至少需要 FY2022、FY2023、FY2024、FY2025 四个年度端点。未达到门槛的证券状态为 pending_evidence/history_not_mature，不生成正式分数。周期行业额外要求完整连续的 5 个年度观察点，缺少任一年即不评分。

任何内部指标若要求更长窗口，仍必须满足该指标窗口，且不允许缩短窗口、替换为两年 CAGR 或重分配权重。三年 CAGR 需要四个年度端点；连续性指标、正常化指标或质量指标若在注册表中要求五年，则需要 FY2021 至 FY2025。全局最低历史门槛是必要条件而非对各指标窗口的豁免。

最近 8 个可比季度使用截至冻结日可见的连续季度序列；对 2026H1 首发，目标序列为 2024Q3 至 2026Q2。中国累计披露口径下，duration 项按 Q1=Q1累计、Q2=H1累计-Q1累计、Q3=Q3累计-H1累计、Q4=FY累计-Q3累计 逐项拆分；instant 项使用各季度末时点值。参与相减的两个事实必须使用同一证券、同一会计口径、同一版本选择规则，任一项缺失或冲突即不生成该季度事实。

### 6.2 置信度

令 D、P、H、K 均落在 0 到 1：

~~~text
C = 0.60 + 0.40 × (0.30D + 0.25P + 0.25H + 0.20K)
~~~

| 输入 | 可计算定义 |
|---|---|
| D：完整度 | 已验证的、模板适用的评分槽位权重占比。所有必需评分槽位必须已验证；不得用 0、行业中位数或默认值填补。模板明确不适用的槽位不进入分母。 |
| P：时点可靠度 | 按评分槽位权重汇总：有可验证公开时分秒且不晚于冻结日为 1；仅有官方日期、但其有效时点不晚于冻结日为 0.8；无法验证时间的值不能进入正式评分。 |
| H：历史长度 | 连续完整 FY 年度观察点数除以 5，最大为 1。正式评分至少需要四个端点，因此 H 的最小正式值为 4/5；FY2021 至 FY2025 的连续五个端点为 1。 |
| K：口径一致性 | 所有必需事实均来自单一、已验证、版本固定的映射和模板为 1；存在未消解的口径冲突则不评分。 |

令 q_i 为第 i 个模板适用评分槽位的全局权重，即七维总权重乘以该维内部权重，并在所有适用槽位上归一化。D 等于已验证槽位的 q_i 之和；P 等于各槽位 q_i 与其时点分的加权和。一个槽位由多个原始事实构成时，使用其中最低的时点分。正式评分要求 D=1 且 K=1；经登记的无一致预期覆盖是一个已验证的中性槽位，不降低 D。

无一致预期覆盖后的 C 上限见 4.3。C 只反映证据质量，不得把缺失维度的权重重新分配给其余维度。按当前严格合同，formal_scored 的 D=1、K=1、P 不低于 0.8、H 不低于 0.8，因此 C 在无一致预期时不低于 0.90、其余情况下不低于 0.96。C≥0.75 作为强池和等待池的防御性断言保留，但在本版本的严格证据门槛下不构成额外筛选；若要令该门槛具有新的筛选作用，必须另行修改已批准的 C 公式或资格政策。

### 6.3 五个模板与指标注册表

模板注册表必须为每个内部指标指定：

- 原始公式、分子分母、期间、单位和方向；
- 可用的金融行业概念等价替代项；
- 必需或支持性证据属性；
- 适用的绝对红线、封顶和周期规则；
- 证据字段、事实 ID、公式版本和映射版本。

同一维度的内部权重在所有模板中不变。某工业指标不适用金融机构时，只能由注册表中的概念等价指标替换；不能静默删除后重分配权重。

## 7. 分位数、七维分数与总分

### 7.1 同行分位数

连续指标先在“模板 × 申万 2021 二级行业”的 metric_peer_eligible 证券中比较。metric_peer_eligible 是指标级状态：证券属于冻结 A 股宇宙、具有该指标全部必需且已验证的截止日前事实、拥有有效模板和行业归属、且该指标没有无效分母或未消解冲突。它不要求该证券已拥有全部七维分数，也不要求可入池；因此不会与 formal_scored 形成循环依赖。有效样本数少于 20 时，回退到同模板的一级行业；仍少于 20 时，不生成正式分数。

对于方向为正的指标：

~~~text
metric_score = 100 × (average_rank - 0.5) / N
~~~

average_rank 使用并列值的平均秩。方向为负的指标使用 100 - metric_score。原始值为负、零或极端但经济含义明确时按实际方向、排名和红线处理；缺失、无效分母或无法解释的值不得伪造数值。百分位本身已降低极端值对横截面分数的影响，原始比率只可按已版本化的经济定义作必要边界校验。

### 7.2 七维内部构成

| 维度 | 总权重 | 内部构成 |
|---|---:|---|
| 成长 G | 18% | 每股经营利润三年 CAGR 35%、最新同比 25%、营收或经营收入三年 CAGR 25%、最新同比 15%。 |
| 估值 V | 18% | 归一化盈利收益率 45%、归一化自由现金流收益率 25%、EV/EBIT 或 PB-可持续 ROE 30%。 |
| 商业质量 M | 18% | ROIC/ROE 持续性 40%、利润率/NIM 持续性 30%、现金转换或资产效率 30%。 |
| 盈利质量 EQ | 12% | 经营现金流/经营利润 35%、应计质量 25%、核心利润占比 20%、营运资本质量 20%。 |
| 财务安全 FS | 8% | 杠杆或监管资本 40%、流动性或利息覆盖 35%、资产风险或或有负债 25%。 |
| 资本配置 CA | 16% | 回报率持续性 35%、增量资本回报 30%、分红回购与稀释 20%、并购/商誉/资本开支纪律 15%。 |
| 买点 T | 10% | 相对历史估值 35%、价格趋势与波动 25%、预期变化 25%、可量化事件日历与流动性风险 15%。 |

金融模板在保留经济含义与权重的前提下，以监管资本、资产质量、净息差、偿付能力、净资本或其他已登记的等价事实替换不适用的工业指标。

T 的最后一项只能使用状态注册表中预先定义、可量化、日期可验证的日历事件与流动性指标。重大诉讼、事故、政策冲击、控制权争夺和其他无法可靠量化概率/影响的事项不得以伪精确分数进入 T，必须留在独立事件状态或池否决路径。

### 7.3 周期保护与绝对红线

周期行业清单必须作为 release 合同的一部分冻结并版本化，不能在运行时临时判断。对于该清单内的证券，若滚动 ROE 与营业利润率均处在其自身连续五年历史的 80 分位或以上：

- 成长 G 和商业质量 M 的最终分数均不高于 80；
- 估值使用当期利润和五年利润中位数中较低者进行正常化；
- 无完整五年历史时，证券不生成正式分数。

绝对红线由模板化、版本化的 redline registry 定义。每条规则必须声明来源字段、阈值、适用模板和结果（模块封顶、池否决或待补证据）。注册表缺失、版本未冻结或证据不足时，正式发布失败关闭；不得以主观文字或手工调整替代数值规则。

### 7.4 总分、基础分与风险

~~~text
S0 = 0.18G + 0.18V + 0.18M + 0.12EQ + 0.08FS + 0.16CA + 0.10T
Sc = 50 + C × (S0 - 50)

Sbase = (0.18G + 0.18V + 0.18M + 0.12EQ + 0.08FS + 0.16CA) / 0.90
B = 50 + C × (Sbase - 50)

R安全 = 0.40FS + 0.25EQ + 0.20M持续性 + 0.15CA下行保护
风险暴露 = 100 - R安全
~~~

令 M回报持续性、M利润率持续性、CA股东回报与反稀释、CA资本纪律分别为第 7.2 节相应子项的 0–100 分：

~~~text
M持续性 = (0.40 × M回报持续性 + 0.30 × M利润率持续性) / 0.70
CA下行保护 = (0.20 × CA股东回报与反稀释 + 0.15 × CA资本纪律) / 0.35
~~~

报告同时展示 G、V、R安全、风险暴露、T、七维分数、Sc、B 和 C。等级带为 90–100 A+、80–89 A、70–79 B、60–69 C、50–59 D、0–49 E；所有入池判断使用精确分数而非等级带。

## 8. 池否决、资格与确定性选择

### 8.1 硬否决

以下情形可以保留评分和审计轨迹，但一律禁止进入强烈关注和等待合适价格两个池：

- 冻结日为 ST 或 *ST；
- 退市整理、强制退市风险或已验证的治理红灯；
- 归属股东权益或净资产非正；
- 审计报告为保留意见、否定意见或无法表示意见；
- 冻结日前连续 20 个交易日无有效成交；

未消解的重大证据冲突属于 pending_evidence，而不是池否决。治理橙灯、拥挤、重大解禁/减持窗口、重大事件和周期顶部状态不混入基本面均分。它们必须作为独立、带证据的状态；状态注册表决定其是禁止强池、仅可等待、或禁止双池。

### 8.2 入池资格

| 池 | 必须同时满足 |
|---|---|
| 强烈关注 | Sc ≥ 70、C ≥ 0.75、M/EQ/FS 各 ≥ 45、T ≥ 55，且无硬否决或强池禁止状态。 |
| 等待合适价格 | B ≥ 65、C ≥ 0.75、M/EQ/FS 各 ≥ 45、T < 55，且无硬否决或等待池禁止状态。 |

两个池天然互斥。未通过强池容量上限的强池资格证券不得自动转入等待池；不满足任一资格的证券不得因为估值低或排名靠前进入池。

### 8.3 容量、排序和行业上限

在资格过滤后，逐证券按固定键选择：

- 强烈关注：Sc 降序、C 降序、R安全 降序、security_id 升序；最多 20 只；
- 等待合适价格：B 降序、C 降序、V 降序、security_id 升序；最多 50 只。

二级行业容量按冻结的申万行业分别计算：强池每个行业至多 4 只，等待池每个行业至多 10 只。按排序顺序扫描候选：候选所属行业已达上限时跳过该候选，继续扫描其他行业候选；仅在全池达到 20 或 50 上限时停止。被强池行业上限跳过的证券不转入等待池。相同输入必须逐字节产生相同排序和成员。

## 9. 分数运行、发布闸门与不可变产物

### 9.1 输入哈希与运行身份

正式 score run 的 input_hash 至少包含：

- universe_hash、冻结日和交易日历哈希；
- 每只证券的 feature bundle hash；
- 市场、行业、治理、事件和一致预期的已验证快照哈希；
- 指标注册表、模板、红线、状态和评分合同版本；
- 池容量、行业上限和选择算法版本。

release_id 是确定性内容身份，至少包含冻结日、合同版本和完整 input_hash；evidence_manifest_hash 是 input_hash 的必含组成。可读格式可以使用 input_hash 前缀，但数据库必须保存完整 input_hash 并施加唯一性约束。运行过程可继续使用随机 score_run_id；同一输入不得产生两个不同的正式 release_id，任一输入变化必须形成新 release_id，旧发布保持可读取。

正式发布先在与 data/releases 相同卷的 staging 目录写入全部文件并计算逐文件 SHA-256。FormalReleaseValidator 验证目录、全部文件哈希与发布清单后，先写入包含完整文件哈希表的 release_manifest，再以原子重命名提交到 data/releases/<release_id>/。目标目录已经存在时，仅当清单和所有文件逐字节一致才视为幂等成功；任何半写、哈希不符或内容冲突均标记 blocked，绝不覆盖既有发布。

### 9.2 发布前验证

finalize 前必须验证：

1. 全量宇宙 100% 有且仅有一个状态；
2. 每个 formal_scored 证券具备七维、Sc、B、R安全、C、同行样本和全部必需证据；
3. 每个评分输入均不晚于冻结时间，且哈希、请求身份、证券和报告期一致；
4. 无正在租用的正式作业，无未解释的错误，无无效或重复 score item；
5. 两池互斥、容量和行业上限正确，排序键和逐条选择记录完整；
6. canonical formal_pool_counts 只使用 strong 与 wait 两个键，并与实际成员逐项一致；旧 official_pool_counts 的 strong_attention/waiting_price 只能由兼容读取层转换，不得作为正式写入格式；
7. 所有待补、否决和范围外原因都可追溯到状态和证据。

任一项失败，run 只能标记 blocked 或 preview，禁止产生 official release。实现必须新增 FormalReleaseValidator，并仅允许带有其验证清单哈希的调用进入 finalize。禁止没有全量 universe_status 清单的空分数 run，或只有 ready 标志而没有验证清单的 finalize；当全量宇宙均已分类但正式评分数为 0 时，仍可形成明确写明零覆盖的正式发布。

### 9.3 发布包

每个正式发布目录至少包含：

- release_manifest.json：合同、哈希、时间、运行结果和计数；
- universe_status.parquet 或 CSV：每只 A 股的状态和原因；
- scores.parquet 或 CSV：七维、Sc、B、R安全、风险暴露、C、同行信息和等级；
- strong_attention.csv 与 waiting_price.csv：成员、排序键、行业容量和入选理由；
- evidence_manifest.json：原始快照、事实、特征和来源引用；
- audit_cards/：每只正式评分证券的关键证据、红线、周期状态和可复算路径；
- quality_report.md：覆盖、待补、否决、重试和发布闸门结论。

发布文件位于已保留的数据目录中。临时报告、渲染缓存、WAL/SHM 和进度 UI 文件不得充当发布证据。

## 10. 验证、测试与验收

实现必须包含以下层次的验证：

- 单元测试：指标公式、方向、分位数并列、C、S0、Sc、B、R安全、阈值、周期保护、红线和排序；
- 契约测试：来源身份、哈希、披露时点、无一致预期、模板替换、证据缺失和行业回退；
- 数据库与恢复测试：幂等入队、租约、断点恢复、重试、单表成功不丢失、输入变化只重算受影响证券，以及旧快照不能伪装成已验证正式快照；
- 时点与期间测试：15:00 收盘门槛、同日盘后披露排除、BJ 六位代码、停复牌状态、累计报表拆分为独立 Q2/Q4、三年与五年窗口；
- 端到端测试：官方发布成功、任何一只未分类阻断、未来数据阻断、无 universe_status 的空 score run 阻断、容量和互斥断言、行业满额后继续扫描其他行业；
- 可复现性测试：相同夹具和相同 input_hash 的产物、排序、计数和清单一致；
- 敏感性报告：使用本 V3 的权重 ±5 个百分点、阈值 ±10 分、模板与关键会计调整变更对成员的影响。

验收不以凑满 20/50 为目标。只有所有发布闸门通过后，实际成员数才可称为正式结果；0 是合法的正式容量结果。

## 11. 实施边界与后续步骤

本规格批准后，实施顺序为：

1. 迁移正式快照元数据、全量 universe_status、BJ 证券身份、季度事实和确定性 release 身份；旧 score_item 与旧 23:59:59 截止逻辑不得被冒充为正式合同；
2. 接入并验证市场、行业、公告、治理、事件与一致预期的原始来源，完成来源白名单和验签解析，扩展全量沪深北 A 股增量任务；
3. 将五模板指标、周期行业、红线和状态注册表的具体字段、阈值、适用性与版本作为受测配置签入；未冻结的注册表不得触发正式发布；
4. 实现模板指标、分位数、C、红线、周期保护、评分和双池选择，并由 FormalReleaseValidator 连接正式 finalize；
5. 加入发布包、审计卡、恢复报告和全套自动化测试；
6. 仅在全量宇宙状态和证据合同通过后，生成 2026-08-31 的首个官方 release。

在完成上述实现和验证前，现有 feature-contract-v1、预筛分数和 120 只深抓进度必须继续明确标记为非正式，不得对外表述为本合同的正式评分或股票池。
